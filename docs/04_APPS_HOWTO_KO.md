# ArmPi 조종 앱 켜는 법 (Mac 앱 · Android 앱 · 휴대폰 브라우저)

작성 2026-11-02. 대상: ArmPi Pro(메카넘 4륜 + 5축 팔 + 그리퍼 + USB 카메라, Raspberry Pi 4B, Ubuntu 22.04 + ROS 2 Humble 이미지).

> **시험 상태**: 이 문서의 절차는 **이 맥에서 가짜 로봇(`protocol_v3/mock_robot.py`)으로만** 확인했다. 실제 로봇, 실제 휴대폰(Android WebView), 실제 와이파이 지연, 대체 AP, 로봇 안의 `armpi-web.service`는 아직 시험하지 않았다(8절).

## 0. 한눈에

| 방법 | 받을 파일 | 연결 대상 | 조종기 서버가 도는 곳 |
|---|---|---|---|
| **Mac 앱** | `output/ArmPi_Controller_mac.zip` | 로봇 주소(`auto` 또는 IP) | 맥 안(앱이 띄움) → 로봇 UDP 5001 |
| **Android 앱** | `output/ArmPi_Controller_android.apk` | "로봇 찾기" 또는 IP | 로봇 안(`armpi-web.service`, 포트 18765) |
| **휴대폰 브라우저** | 없음 | `http://<로봇IP>:18765/mobile` | 로봇 안(같은 서비스) |

```
[Mac 앱] ─ 맥 안의 조종기 서버 ─ UDP 5001 ─┐
                                           ├─▶ 로봇: v3 수신기(armpi.service) → 바퀴·팔
[휴대폰] ─ http://<로봇IP>:18765/mobile ─ 로봇 안의 웹 조종기(armpi-web.service) ─ UDP 127.0.0.1:5001 ─┘
```

세 방법 모두 같은 안전 경로(Protocol v3: 중립 확인 뒤 출발, 입력 0.3 s 끊기면 중립, 로봇 watchdog 0.4 s, 비상정지 latch)를 쓴다. 로봇은 **한 번에 한 조종기 세션**만 받는다.

## 1. 시작 전 준비 (공통)

1. 로봇에 ROS 2 이미지가 올라가 있고 `armpi.service`(제어·v3 수신기·카메라·rosbridge)와 `armpi-web.service`(휴대폰용 웹 조종기)가 켜져 있어야 한다. 둘 다 부팅 때 자동으로 켜진다(`deploy/systemd/ENABLED`).
   - **로봇에 SD 카드가 꽂혀 있으면 켜기 전에 반드시 뺀다.** 꽂힌 채 켜면 예전 시스템 커널로 섞여 부팅되고(와이파이·카메라 안 됨), SD 카드 내용이 바뀔 수 있다.
   - v2 부터 로봇 안 웹 조종기는 C++ 노드(`armpi_web_gateway`)다. 화면·HTTP API·안전 규칙은 v1(파이썬)과 같다(`13_SOFTWARE_ARCHITECTURE_KO.md`).
2. 조종 기기와 로봇을 **같은 와이파이**에 둔다.
   - **와이파이 우선순위: 1순위 와이파이 → 2순위 와이파이 → 대체 AP.** 1순위가 보이지 않으면 2순위로 붙는다(이미지를 만들 때 설정).
   - 기본: 연구실 와이파이 **1순위 와이파이**.
   - 로봇이 부팅 뒤 60 s 안에 1순위 와이파이에 못 붙으면 **대체 AP**를 켠다: 이름 **`ArmPi-ROS2`**, 2.4 GHz(비밀번호는 문서에 적지 않음(담당자에게 확인)). 휴대폰·맥을 이 AP에 연결하면 로봇 주소는 **`192.168.149.1`**이다.
3. 로봇 IP 알아내기: Android 앱의 "로봇 찾기", Mac 앱의 `auto`, 공유기의 접속 기기 목록, 또는 맥에서 `armpi-ros2.local`(mDNS 이름).
4. **안전 준비**(6절): 처음에는 바퀴를 띄우고, 팔이 닿는 범위를 비우고, 전원 스위치를 손 닿는 곳에 둔다. 속도는 10–30 %로 낮춰 시작한다(휴대폰 화면 기본은 60 %).

## 2. Mac 앱

### 2.1 설치

1. Finder에서 `output/ArmPi_Controller_mac.zip`을 더블클릭한다. 같은 폴더에 **`ArmPi Controller.app`**이 생긴다.
2. (선택) `응용 프로그램` 폴더로 끌어 옮긴다.

요구 사항: macOS 12 이상, **Apple Silicon(arm64) 맥**. 앱 안의 조종기는 맥 기본 `/usr/bin/python3`로 돈다. 명령줄 도구가 없는 맥이면 처음에 설치 안내 창이 뜨거나 앱이 "python3 가 없습니다"라고 알려 준다 → 터미널에서 `xcode-select --install`.

직접 다시 빌드하려면(Xcode 필요 없음, Command Line Tools의 `swiftc`만 사용):

```bash
cd ArmPro_Cpp_ROS2
bash clients/mac_app/build_mac_app.sh            # → output/ArmPi_Controller_mac.zip
bash clients/mac_app/build_mac_app.sh --install  # 위 + ~/Applications/ArmPi Controller.app
```

### 2.2 처음 열 때 (Gatekeeper)

이 앱은 개발자 인증서 없이 **ad-hoc 서명**만 돼 있다. 이 맥에서 빌드해 연 앱은 보통 경고 없이 열린다. zip을 다른 맥으로 옮기거나 메신저·메일로 받았다면 "확인되지 않은 개발자" 경고가 날 수 있다.

- Finder에서 앱을 **Control-클릭 → 열기 → 열기**.
- macOS 15 이상에서 위 방법이 안 되면: 한 번 열기를 시도한 뒤 **시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 "그래도 열기"**.
- 터미널로 한 번에: `xattr -dr com.apple.quarantine "/Applications/ArmPi Controller.app"`

로봇에 처음 붙을 때 **"로컬 네트워크의 기기를 찾고 연결하도록 허용하겠습니까?"** 창이 뜨면 **허용**한다. 거부했다면 시스템 설정 → 개인정보 보호 및 보안 → 로컬 네트워크에서 ArmPi Controller를 켠다.

### 2.3 연결하기

1. 앱을 연다. 첫 화면에 **로봇 주소** 칸이 있다(지난번 값이 들어 있음).
   - `auto` = 같은 와이파이에서 자동 검색(UDP 5002, 2 s). 여러 대면 첫 번째 로봇.
   - IP 직접: 예) `192.168.0.50`, 대체 AP면 `192.168.149.1`, 또는 `armpi-ros2.local`.
   - 목록 화살표를 누르면 최근 주소가 나온다.
2. **연결**(Enter). 조종 화면이 열린다(브라우저용 PC 화면과 같다).
3. 끝낼 때는 **⌘Q**. 앱이 조종기에 중립과 `disconnect`를 보내게 한 뒤 끝난다. 앱이 비정상 종료돼도 조종기가 스스로 중립·`disconnect`를 보내고 끝난다.

메뉴 **로봇**:

| 메뉴 | 단축키 | 하는 일 |
|---|---|---|
| 다시 연결 | ⌘R | 같은 주소로 조종기를 다시 시작(새 세션) |
| 로봇 주소 바꾸기… | ⌘L | 조종기를 끄고 첫 화면으로 |
| 기본 브라우저에서 열기 | | 같은 조종 화면을 Safari·Chrome에서 |
| 조종기 로그 보기 | | `~/Library/Logs/ArmPi Controller/controller.log` |

조종 화면 포트는 18765부터 비어 있는 번호를 쓴다(이 맥의 8765는 다른 프로그램이 사용 중). 창 제목에 실제 포트가 나온다.

### 2.4 키 배치

**조종 화면을 한 번 클릭해야 키가 들어간다.** 다른 창으로 가면(포커스를 잃으면) 자동으로 중립이 된다.

| 키 | 동작 |
|---|---|
| **W / S** | 앞 / 뒤 (누르는 동안만) |
| **A / D** | 왼쪽 / 오른쪽 **평행이동**(메카넘) |
| **Q / E** | 제자리 좌회전 / 우회전 |
| 속도 슬라이더 | 10~100 %(기본 30 %). 100 % = 로봇 설정 상한(앞뒤·좌우 0.25 m/s, 회전 1.2 rad/s — 사용자 결정 2026-11-04, 바퀴 방향 실기 시험 전) |
| **Space** | **비상정지** |
| "비상정지 해제" | 해제 뒤에는 키를 모두 뗐다가 다시 눌러야 출발 |
| "팔 조종 켜기" | 팔 채널 켜기. 켠 뒤에만 아래 키가 움직인다 |
| **I / K** | 손끝 앞 / 뒤 (x) |
| **J / L** | 손끝 왼쪽 / 오른쪽 (y) |
| **U / O** | 손끝 위 / 아래 (z) |
| **R / F** | 손목(pitch) 위 / 아래 |
| **G / H** | 그리퍼 닫기 / 열기 |

자세한 화면 설명은 `clients/mac_controller/README_KO.md` 2절.

### 2.5 로봇 없이 연습하기 (가짜 로봇)

```bash
cd ArmPro_Cpp_ROS2
python3 protocol_v3/mock_robot.py --bind 127.0.0.1
```

앱 첫 화면에서 주소를 `127.0.0.1`로 넣고 연결한다. 가짜 카메라 영상(격자 + 노란 점)과 상태가 나온다.

## 3. Android 앱

### 3.1 설치 (APK)

파일: `output/ArmPi_Controller_android.apk` (약 45 KB). Android **8.0(API 26) 이상**.

**휴대폰으로 옮기기** — 셋 중 편한 것:

- **USB 케이블**: 휴대폰을 맥에 꽂고, 휴대폰 알림에서 USB 용도를 **"파일 전송"**으로 바꾼 뒤 APK를 `Download` 폴더에 복사한다. 맥은 기본으로 Android 파일 전송(MTP)을 지원하지 않아 별도 파일 전송 앱이 필요할 수 있다(새 프로그램 설치는 직접 판단).
- **같은 와이파이로 받기**(새 프로그램 필요 없음): 맥에서
  `python3 -m http.server 8000 --bind 0.0.0.0 --directory output` 을 실행하고, 휴대폰 Chrome에서 `http://<맥 IP>:8000/` → `ArmPi_Controller_android.apk`를 누른다. 다 받으면 맥 터미널에서 Ctrl+C. (맥 IP: 시스템 설정 → Wi‑Fi → 세부사항)
- USB 메모리(OTG)나 직접 보내기 등 다른 방법도 된다.

**설치하기**:

1. 휴대폰의 **파일**(내 파일) 앱 → Download → `ArmPi_Controller_android.apk`를 누른다.
2. "보안상 이 출처의 알 수 없는 앱을 설치할 수 없습니다"가 나오면 **설정 → 이 출처 허용**(알 수 없는 앱 설치 허용)을 켜고 뒤로 돌아온다.
3. **설치**. Play 프로텍트가 "알 수 없는 앱"이라고 경고하면 **세부정보 → 무시하고 설치**(디버그 키로 서명한 연구용 앱이라 뜨는 경고).
4. 다 쓰면 2의 허용은 다시 꺼 두는 편이 안전하다.

**업데이트**: 새 APK를 그대로 설치하면 덮어쓴다(빌드할 때 만든 같은 디버그 키로 서명). "기존 패키지와 충돌" 오류가 나면 서명 키가 바뀐 것이므로 앱을 지우고 다시 설치한다.

직접 다시 빌드하려면(Gradle 필요 없음): `bash clients/android_app/build_apk.sh` → `output/ArmPi_Controller_android.apk`.

### 3.2 연결하기

1. **ArmPi 조종기** 앱을 연다. 화면은 가로로 고정되고, 켜 두는 동안 꺼지지 않는다.
2. 열리자마자 **로봇 찾기**(2 초)를 한다. 왼쪽 목록에 `이름  IP  → 연결`이 나오면 누른다.
3. 목록에 없으면 오른쪽 칸에 IP를 넣고 **연결**. 최근에 쓴 IP는 칸 아래 버튼으로 다시 고를 수 있다.
4. 연결되면 전체 화면 조종 화면(`http://<IP>:18765/mobile`)이 열린다.
5. **뒤로 가기** = 중립·조종권 놓기를 보내고 첫 화면으로.
6. 홈 버튼으로 나가거나 다른 앱으로 바꾸면 즉시 중립을 보내고, 1.5 s 뒤 조종권이 풀린다.

연결 실패 문구가 나오면 7절 문제 해결을 본다.

### 3.3 조종 화면 쓰는 법 (Android 앱·휴대폰 브라우저 공통)

```
┌ 연결 · 차체 · 팔 · 배터리 · ACK · 조종권 ─────────────── [영상] [전체] [메뉴] ┐
│                         ( 비상정지 )            [팔 조종 켜기] [기본 자세]     │
│   ( 조이스틱 )          [길게 눌러 해제]               앞     위로  손목↑    │
│   앞·뒤·옆으로           안내 문구              왼쪽 손끝 오른쪽 아래로 손목↓  │
│ [속도 30% 60% 100%]                                  뒤     열기  닫기      │
│                                                ◀ 좌회전 (회전 슬라이더) 우회전 ▶ │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 조작 | 동작 |
|---|---|
| **왼쪽 조이스틱** | 위/아래 = 앞/뒤, 왼/오른쪽 = 옆으로 평행이동(메카넘). 미는 만큼 빨라진다. **손을 떼면 바로 정지** |
| 속도 30 / 60 / 100 % | 조이스틱·회전의 최대값. 기본 60 %(로봇 설정 `ui_default_speed`, 화면에 저장된 값이 있으면 그것). 100 % = 로봇 설정 상한(0.25 m/s, 1.2 rad/s — 사용자 결정 2026-11-04, 바퀴 방향 실기 시험 전) |
| **오른쪽 아래 회전 슬라이더** | 왼쪽으로 밀면 좌회전, 오른쪽이면 우회전. 손을 떼면 가운데로 돌아가 정지 |
| 두 손가락 | 조이스틱과 회전을 동시에 쓸 수 있다 |
| **빨간 비상정지** | 닿는 순간 비상정지(휴대폰 진동). 바퀴 정지, 팔은 그 자리에서 힘을 유지 |
| **길게 눌러 해제** | 0.8 초 길게 눌러야 해제(실수 방지). 해제 뒤 **손을 모두 뗐다가** 다시 조작, 팔은 "팔 조종 켜기"를 다시 |
| **팔 조종 켜기** | 켠 뒤에만 팔 버튼이 동작. 다시 누르면 끔(팔은 그 자리에 멈춤) |
| 팔 버튼(앞·뒤·왼쪽·오른쪽·위로·아래로·손목) | **누르고 있는 동안** 손끝 목표가 일정 속도로 움직인다(0.15 m/s, 손목 0.6 rad/s. 로봇 설정 `arm_speed`) |
| 열기 / 닫기 | 누르는 동안 그리퍼가 열리거나 닫힌다(0 = 완전히 열림, 1 = 완전히 닫힘) |
| 기본 자세 | 팔 조종이 켜져 있으면 목표를 기본 자세로 옮기고, 꺼져 있으면 로봇의 기본 자세 서비스를 부른다 |
| 위쪽 상태 줄 | 로봇 연결, 차체·팔 채널 상태, 배터리, ACK 지연(150 ms 넘으면 노랑), 조종권, rosbridge |
| 연결 없이 비상정지 | 조종권이 없을 때 비상정지를 누르면 비상정지는 바로 로봇에 간다. 이때 연결 칩은 "대기 · 비상정지 보냄"→"대기"로 남고("로봇 연결"로 바뀌지 않음), "비상정지 ON"과 조종권 "없음"이 보인다. 보내려고 잠깐 연 세션은 2 s 뒤 닫힌다(`/api/state` 의 `session.reason` = `estop_only`) |
| 영상 | 배경 → 작게 → 끔 순서로 바뀐다 |
| 메뉴 | 연결(새 세션), 연결 끊기, 조종권 놓기, 팔 목표 = 로봇 현재값, 로봇 전체 정지·전체 해제, 상세 상태, 최근 사건 |

- 팔 목표가 거부되면(작업 공간 밖, 도달할 수 없는 자세) 아래쪽에 빨간 알림이 뜨고 목표가 마지막으로 받아들여진 위치로 돌아간다. 계속 거부되면 **기본 자세**를 누른다.
- 휴대폰을 세로로 들면 "가로로 돌려 주세요"와 비상정지 버튼만 보인다(조작은 중립).
- 화면이 꺼지거나 다른 앱으로 가거나 와이파이가 끊기면 0.3 s 안에 중립이 된다(로봇 쪽 watchdog도 0.4 s).

### 3.4 조종권 (여러 기기가 같은 로봇을 열었을 때)

- 로봇 안의 웹 조종기는 **한 화면만** 조종하게 한다. 조종권이 비어 있을 때 **먼저 조작한 화면**이 갖는다.
- 다른 화면에는 **"다른 기기가 조종 중: <기기> (<IP>)"**가 뜨고 조작이 무시된다. **비상정지는 어느 화면에서나 된다.**
- 가져오려면 **조종권 가져오기**를 두 번 누른다(가져오면 이전 화면의 입력은 중립이 되고 팔 조종도 꺼진다).
- 조종권은 그 화면이 1.5 s 동안 아무 요청도 없거나(닫힘·백그라운드), **60 s 동안 조작이 없으면** 풀린다. 풀리면 로봇 세션도 닫혀 VR 등 다른 조종기가 로봇을 쓸 수 있다.
- Mac 앱(맥 안 조종기)과 휴대폰(로봇 안 조종기)은 서로 다른 조종기다. 한쪽이 로봇을 쓰는 중이면 다른 쪽에는 "로봇을 다른 조종기(VR 등)가 쓰는 중입니다"가 뜬다. 한 번에 한 조종기만 쓴다.

## 4. 휴대폰 브라우저로 바로 열기 (앱 없이)

1. 휴대폰을 로봇과 같은 와이파이에 연결한다.
2. Chrome 주소창에 **`http://<로봇IP>:18765/mobile`** (예: `http://192.168.149.1:18765/mobile`). `http://<로봇IP>:18765`만 쳐도 휴대폰이면 자동으로 `/mobile`로 간다.
3. 가로로 들고, 오른쪽 위 **전체** 버튼을 누르면 전체 화면이 된다(가로 고정도 시도).
4. 다음부터 빨리 열려면 Chrome 메뉴(⋮) → **홈 화면에 추가**. 아이콘과 이름 "ArmPi"가 생긴다(암호화되지 않은 http 주소라 정식 앱 설치가 아니라 바로가기로 추가된다).
5. 브라우저에서는 화면 꺼짐을 막을 수 없다. 화면이 꺼지면 중립이 되고 조종권이 풀린다. 오래 쓸 때는 Android 앱을 쓰거나 화면 자동 꺼짐 시간을 늘린다.

- 키보드가 있는 노트북에서는 `http://<로봇IP>:18765/index.html`이 PC 화면이다.
- iPhone Safari에서도 열리게 만들었지만 시험하지 않았다.

## 5. 로봇 쪽: 웹 조종기 서비스

> 이미지 v2(2026-11-04)부터 이 서비스는 C++ 노드 `armpi_web_gateway_node`다(같은 포트 18765, 같은 화면·API). 구조는 `13_SOFTWARE_ARCHITECTURE_KO.md`. 아래 표는 v1 기준 기록이다.

| 항목 | 값 |
|---|---|
| 유닛 | `deploy/systemd/armpi-web.service` (부팅 시 자동, `deploy/systemd/ENABLED`) |
| 실행 | `/usr/bin/python3 /opt/armpi/mac_controller/armpi_mac_controller.py --robot 127.0.0.1 --bind 0.0.0.0 --http-port 18765 --no-browser` |
| 필요한 파일 | `/opt/armpi/mac_controller/`(armpi_mac_controller.py, index.html, mobile.html, manifest.webmanifest, icon-192.png, icon-512.png) + `/opt/armpi/vr_protocol_v3/armpi_v3_client.py` |
| 세션 방식 | `--bind 0.0.0.0`이면 자동으로 **on-demand**: 조종권을 잡은 화면이 있을 때만 로봇과 v3 세션을 연다 |
| 상태 보기 | `systemctl status armpi-web`, 로그 `journalctl -u armpi-web -f` |
| 끄기·켜기 | `sudo systemctl stop armpi-web` / `sudo systemctl start armpi-web` |

휴대폰 화면은 **인증 없이** 같은 망의 누구나 열 수 있다(로봇 제어 UDP와 같은 수준). 여러 사람이 쓰는 망보다 대체 AP나 전용 공유기에서 실험하는 편이 안전하다.

## 6. 안전

- **처음에는 바퀴를 띄운다**(차체 밑에 받침). 메카넘은 옆·대각선으로도 움직인다.
- **팔이 닿는 범위를 비운다.** 손·케이블이 그리퍼와 관절 사이에 끼지 않게 한다.
- 화면의 비상정지는 **소프트웨어 정지**다(UDP 비상정지). 로봇 프로그램이 멈췄거나 와이파이가 끊기면 전달되지 않을 수 있다. 그때는 로봇 watchdog(0.4 s)이 바퀴를 세운다. **물리적 정지 수단(전원 스위치·배터리 분리)을 항상 손 닿는 곳에 둔다.** 로봇의 KEY1 버튼도 소프트웨어 비상정지다.
- 비상정지가 걸려도 팔은 힘을 유지한 채 그 자리에 선다(떨어지지 않게). 손으로 옮기려면 전원을 끈다.
- 속도 상한(차체 0.25 m/s, 1.2 rad/s, 팔 0.15 m/s)은 사용자 결정 2026-11-04, 바퀴 방향 실기 시험 전에 올린 값이다(이전 0.10/0.60/0.10). 처음에는 속도 버튼을 낮춰 쓰고, 바퀴 방향·바닥 시험(docs/10 C·W) 결과로 다시 정한다.
- ACK 지연 칩이 노랗거나(150 ms 초과) "로봇 응답 없음"이 자주 뜨면 실험을 멈추고 와이파이를 점검한다.
- 배터리 전압이 낮으면 서보 동작이 불안정할 수 있다. 멈추고 충전한다.
- 한 번에 한 사람만 조종한다.
- **켤 때 부저(v2.1부터):** 제어 프로그램이 시작하면 짧게 **1번**(정상), **2번**(경고: 부팅 점검·초기화 경고. 예: SD 카드가 꽂혀 섞여 켜짐), **3번**(fault: 하드웨어 초기화 실패 등)이다. 2·3번이면 조종하지 말고 `/armpi/status`의 `boot_warnings`·`warnings`·`fault_reason`을 본다. 비상정지가 걸릴 때는 0.1 s 한 번 울린다.

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| **로봇이 안 보인다**(로봇 찾기·`auto` 실패) | ① 휴대폰·맥이 로봇과 **같은 와이파이**인가(게스트망·모바일 데이터 아님) ② 로봇이 부팅을 마쳤나(1~2분) ③ 1순위 와이파이 연결에 실패한 로봇은 60 s 뒤 대체 AP **`ArmPi-ROS2`**를 켠다(비밀번호는 문서에 적지 않음(담당자에게 확인)) → 그 AP에 연결하고 **`192.168.149.1`**로 직접 연결 ④ 공유기의 "기기 간 통신 차단(AP 격리)"이 켜져 있으면 검색이 안 된다 → IP 직접 입력 ⑤ VPN을 끈다 |
| 대체 AP에 붙였더니 휴대폰이 "인터넷 없음"이라며 끊으려 한다 | "연결 유지"를 고르고, 잘 안 되면 모바일 데이터를 잠시 끈다 |
| Android 앱: "연결 실패 … 18765" | 로봇의 웹 조종기가 꺼져 있다 → 로봇에서 `systemctl status armpi-web`. IP 오타 확인 |
| 화면은 열리는데 "로봇 응답 없음" | `armpi.service`(v3 수신기)가 꺼져 있거나 재시작 중 → `systemctl status armpi` |
| "로봇을 다른 조종기(VR 등)가 쓰는 중입니다" | 다른 조종기(VR, Mac 앱, 다른 휴대폰)를 끄거나 "연결 끊기". 끊긴 뒤 1 s 안에 다시 잡을 수 있다 |
| "다른 기기가 조종 중" | 그 기기를 닫거나 **조종권 가져오기**(두 번 누름) |
| 비상정지가 안 풀린다 | 메뉴의 "로봇 전체 정지"나 로봇 KEY1으로 건 비상정지는 **메뉴 → 전체 해제**로만 풀린다 |
| 해제했는데 안 움직인다 | 손을 모두 뗐다가 다시 누른다. 팔은 "팔 조종 켜기"를 다시 |
| 팔이 계속 거부된다 | **기본 자세**를 누른다(팔 조종 켠 상태) |
| 영상 없음 | 카메라 연결과 `armpi.service`의 영상 서버(8080) 확인. 영상 버튼이 "끔"인지 확인. 영상이 없어도 조종은 된다. 브라우저로 직접 열 때는 주소에 `qos_profile=sensor_data`를 붙인다 |
| 조종이 갑자기 전부 거부된다(화면에 "다른 조종기가 쓰는 중", 로그에 `control_state 2.000s 넘게 미수신`) | 로봇 안 ROS 통신이 막힌 것이다(2026-11-04 실기). 원시 영상을 기본(RELIABLE)으로 받는 창·스냅샷을 닫고, **로봇을 재부팅**한다. 서비스 재시작만으로는 안 풀린 적이 있다(`docs/11` 0절) |
| "rosbridge 미연결" | 배터리·팔 현재값·서비스 버튼만 안 된다. 조종은 된다 |
| Mac 앱: "로봇을 찾지 못했습니다" | IP를 직접 넣는다(대체 AP면 `192.168.149.1`). 로컬 네트워크 권한이 허용됐는지 확인(2.2) |
| Mac 앱: "python3 가 없습니다" | 터미널에서 `xcode-select --install` |
| Mac 앱: 키가 안 먹는다 | 조종 화면을 한 번 클릭한다. 화면의 노란 경고("이 창을 클릭해야…") 확인 |
| Mac 앱이 열리지 않는다(확인되지 않은 개발자) | 2.2 Gatekeeper 절차 |
| Android: 설치가 안 된다 | 알 수 없는 앱 설치 허용(3.1), 저장 공간, "충돌"이면 기존 앱 삭제 후 설치 |

## 8. 시험한 것과 하지 않은 것

**확인함**(2026-11-02, 이 맥, 가짜 로봇 `mock_robot.py --bind 127.0.0.1`, 로그 (시험 기록)):

- 웹 조종기를 `--bind 0.0.0.0`으로 띄웠을 때 `/mobile`·manifest·아이콘 제공, 맥의 LAN 주소로 접속, 다른 Host·Origin 거부.
- HTTP로 넣은 입력이 가짜 로봇에 도달(전진·후진·좌우·회전·팔·그리퍼·비상정지·해제), 두 화면 동시 접속 시 조종권(나중 화면 입력 무시, 비상정지는 허용, 가져오기), 화면이 사라지면 세션 종료.
- 헤드리스 Chrome에서 휴대폰 크기(915×412)로 실제 터치 이벤트(두 손가락 동시 포함)를 넣어 조이스틱·회전·팔 버튼·비상정지·길게 눌러 해제 확인, 스크린샷.
- 기존 조종기 종단 시험(47항목)과 적합성 시험(`conformance_test.py --host 127.0.0.1`) 재통과.
- Mac 앱: 빌드·서명 검증, `open`으로 실행 → 파이썬 서버 18765 응답 → 가짜 로봇 연결, 정상 종료·강제 종료 모두 파이썬 정리와 `disconnect` 확인.
- Android APK: 빌드, `apksigner verify`, `aapt2 dump badging`. 검색 로직은 맥의 Java로 가짜 로봇 상대로 확인(127.0.0.1).

**하지 않음(미시험)**: 실제 로봇, 실제 휴대폰에 APK 설치·실행(Android WebView), iPhone, 실제 와이파이 지연·끊김, 대체 AP, 로봇 안의 `armpi-web.service`, 브로드캐스트 검색(이 시험에서는 실제 망에 브로드캐스트를 보내지 않았다), 다른 맥에서의 Gatekeeper 경고 흐름, Intel 맥.
